## Задачи для реализации в сервере сокетов

### 1. Вывод IP-адреса клиента при подключении
При подключении нового клиента сервер должен обработать событие подключения и извлечь IP-адрес из структуры сокета. Адрес должен быть выведен в консоль.

---

### 2. Проблема с командой `stop`
Сценарий для тестирования команды `stop`:

1. Запустить 4 клиента с разных устройств (не менее 2 компьютеров). Убедиться, что они работают продолжительное время.
2. На сервере выполнить команду `stop`.
   - Команда должна останавливать приём новых клиентов.
3. Попытаться подключить 5-го клиента. Он должен зависнуть, ожидая доступности сервера.
4. Выполнить команду `start`.
   - После выполнения этой команды 5-й клиент должен успешно подключиться.


---

### 3. Проблема с командой `shutdown`
Сценарий для тестирования команды `shutdown`:

1. Запустить 4 клиента с разных устройств (не менее 2 компьютеров). Убедиться, что они работают продолжительное время.
2. Выполнить команду `shutdown`.
   - Консоль сервера должна стать недоступной для ввода новых команд.
3. Аварийно завершить 2 из 4 работающих клиентов.
   - Оставшиеся 2 клиента должны продолжить работу до истечения таймаута.
4. После завершения всех клиентов сервер должен автоматически завершить работу.


---

### 4. Возможность ввода IP-адреса или доменного имени через консоль

Сервер должен быть дополнен функциональностью для ввода IP-адреса или доменного имени через консоль. Это позволяет:
- Гибко задавать настройки подключения.
- Указывать конкретный интерфейс для работы сервера.

**Технические шаги:**
1. При запуске сервера запрашивать IP-адрес или доменное имя.
2. Использовать введённое значение для привязки сокета.

---

### Таймаут
Сервер должен отключать свои сервисы через 3 минуты после простоя (отсутствие активных клиентов). Таймаут необходимо настроить для автоматического завершения работы.

**Примечание:** Особое внимание следует уделить корректной обработке таймаута, чтобы избежать преждевременного завершения или зависания.
